# SecureVote — Complete Production Implementation Plan (FYP)

## Audit conclusion
The README's "production ready / 100% complete" claim is marketing copy. Reality: polished UI prototype with fake data. Flutter app (47 screens) and Next.js admin portal (17 pages) have real UI but everything is hardcoded/localStorage. No real backend, no real auth, no real KYC, no blockchain, 1 boilerplate test, 0 web tests. The 4 crash logs are just VS Code Java LSP OOM errors — not app bugs.

## Locked decisions
Solo dev full-time (40h/wk) · Ship MVP first, blockchain v2 · Node+TS on Cloudflare Workers · D1 (SQLite) + R2 (files) + KV (sessions/cache) · Next.js portal finished (not rebuilt) · Real blockchain on Polygon Amoy testnet (free) · KYC = simulated admin review (documented as future work) · Builds only, no store submission · Short technical doc.

## Target architecture
```
Flutter app ──HTTPS/JWT──> Cloudflare Worker (Hono+Zod) ──> D1 + R2 + KV
                              │
Next.js admin portal (RBAC) ──┘
Polygon Amoy (v2): Voting.sol + chain-listener cron Worker
```

## Phase 1 — Backend foundation (Weeks 2–3)
- `api/` workspace: Cloudflare Worker + **Hono** + **Zod**.
- `migrations/0001_init.sql`: tables `users`, `elections`, `candidates`, `votes` (UNIQUE(election_id,user_id) for anti-double-vote), `audit_log`, `sessions`.
- `wrangler.toml`: bindings `DB` (D1), `STORAGE` (R2), `SESSIONS` (KV).
- Auth routes: `POST /auth/register`, `/verify-otp`, `/login`, `/refresh`, `/logout`, `GET /auth/me`. bcrypt via `@noble/hashes`, JWT via `jose`, email OTP via Resend/EmailJS free tier, KV-backed rate limiting (5/15min).
- Middleware: JWT verify + RBAC (`voter`|`admin`|`verifier`) + audit logging.
- `wrangler d1 create` + execute migration locally and remote; `wrangler deploy` + `wrangler tail`.

## Phase 2 — Flutter → backend (Weeks 4–5)

## Phase 3 — Web portal → backend (Weeks 5–6)
- New `src/lib/api-client.ts` + `auth-context.tsx` (replace `demo-auth.ts`).
- `useApi` hook; wire 17 admin pages to real endpoints (dashboard stats, election CRUD, ballot builder, candidates, voters, KYC queue approve/reject, results, live-monitoring=audit log poll, fraud alerts, audit-log).
- Real RBAC enforced on Worker.
- Deploy web to **Cloudflare Pages** (not Vercel) for single platform.

## Phase 4 — Real KYC + voting (Weeks 7–8)
- KYC: upload ID to R2 (presigned URLs), admin review+approve/reject in `/admin/voters/kyc-verification`.
- `POST /voting/cast`: validate KYC-approved + active election + no duplicate → create vote row + receipt_id (SHA-256 receipt payload) → returns receipt.
- `GET /public/verify/:receiptId` (no auth) — powers `/verifier`. `GET /elections/:id/results` (only when closed, KV-cached).
- Audit-log all actions; notifications endpoint.

## Phase 5 — Hardening & tests (Weeks 9–10)
- Flutter tests (60% coverage: repos + models + login widget). Web tests (Vitest+RTL). API tests via `@cloudflare/vitest-pool-workers`. E2E Playwright (full vote flow + admin flow).
- Security: CORS locked, rate limiting, D1 prepared statements only, CSP header, secrets in `wrangler secret put`, Zod validation everywhere.
- GitHub Actions CI (flutter analyze/test, pnpm --filter api test, web test+build).
- `TECHNICAL_DOC.md` (10–15 pgs): architecture, API ref, schema, deploy guide, security, blockchain roadmap.

## Phase 6 — Blockchain on Polygon Amoy (Weeks 11–12)
- `contracts/` workspace (Hardhat + OpenZeppelin + ethers/viem).
- `Voting.sol`: `createElection`, `commitVote` (prevents double vote on-chain), `finalize(merkleRoot)`. Events for listener.
- Deploy to Amoy (free test MATIC from faucet). `npx hardhat run scripts/deploy.ts --network amoy`.
- Worker `services/blockchain.ts`: on `castVote`, also send `commitVote` tx; store tx_hash + block_number in D1.
- Cron chain-listener Worker syncs `VoteCommitted` events to D1.
- `/public/verify/:receiptId` now returns tx hash + PolygonScan link + Merkle proof.
- Update technical doc with contract design + Merkle construction + why Amoy.
